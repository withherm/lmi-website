# Deploying lmi-website to Cloudflare Workers

Verified in a cloud build on 9 September 2026: config validates, the Worker
boots locally under workerd, all 39 pages serve, unknown paths 404.

## Target

A **Worker with static assets**, not a Pages project. Pages is in maintenance
mode, the Astro Cloudflare adapter targets Workers, and Stripe checkout will
need server routes. EQUIBT stays on Pages until its own cutover.

Worker name: `lmi-website`. Do not create a second one under another name.

## How the config works, and the trap in it

There are two config files and only one of them is hand-edited.

- **`wrangler.jsonc` at the repo root** is the one you edit. It carries the
  name, the compatibility date, the compatibility flags and observability.
- **`dist/server/wrangler.json`** is generated by `@astrojs/cloudflare` on every
  build. It merges the root file and adds `main`, the `ASSETS` binding and the
  `SESSION` KV binding. It is the file you deploy with. Never hand-edit it, it
  is rebuilt each time.

**Do not set `main` or `assets` in the root file.** This adapter emits
`dist/server/entry.mjs` plus `dist/client/`. There is no `dist/_worker.js`.

**The compatibility date cannot run ahead of the installed toolchain.** Setting
it to a date newer than the bundled workerd supports fails the build outright:

```
[ERROR] [vite] service core:user:lmi-website: This Worker requires
compatibility date "2026-09-08", but the newest date supported by this
server binary is "2026-06-18".
```

Current value is `2026-06-18`. Raise it only when wrangler is upgraded.

## Commands

Build and check the deploy bundle without shipping:

```
npm install
npm run build
npx wrangler deploy --dry-run --outdir /tmp/wr -c dist/server/wrangler.json
```

Run the real Worker locally and click through it:

```
npx wrangler dev -c dist/server/wrangler.json --port 8788 --local
```

Deploy:

```
npx wrangler deploy -c dist/server/wrangler.json
```

## Cloudflare dashboard, first time only

Compute > Workers & Pages > Create > Import a repository. Repo
`withherm/lmi-website`, branch `main`, root directory `/`.

- Build command: `npm run build`
- Deploy command: `npx wrangler deploy -c dist/server/wrangler.json`
- Build variables: none. `.node-version` in the repo pins Node 24 and is the
  single source of truth. If a `NODE_VERSION` variable exists in the dashboard,
  delete it, otherwise it overrides the file.

You get `lmi-website.<subdomain>.workers.dev`. That is the review URL.

Note: `lmi.pages.dev` is taken by an unrelated organisation. `lmi-website` is
the name to use.

## Bindings

`SESSION` (KV) is added automatically because the adapter enables Astro
sessions. Every route is currently prerendered so nothing reads it yet, but the
binding must resolve at deploy time. If Cloudflare does not provision it, create
a KV namespace named for the Worker and bind it as `SESSION`.

## Stripe

Secrets go in the dashboard under the Worker's Settings > Variables, never in
`wrangler.jsonc`, which is committed. `STRIPE_SECRET_KEY` and
`STRIPE_WEBHOOK_SECRET` as encrypted Secrets, the publishable key as a plain
variable. Server routes for checkout do not exist yet, so nothing reads them.

## Custom domain, last

`leanmethods.com.au` is not yet a zone in the Cloudflare account. Add the zone,
let it import the Squarespace DNS, check every record against the live ones,
then change nameservers at the registrar. Squarespace keeps serving throughout.
Only once the Worker looks right on workers.dev do you bind apex and www under
Worker > Settings > Domains & Routes.

Do not move nameservers on a live revenue site on a Friday.
